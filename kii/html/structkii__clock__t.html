Detailed Description

The time of day, for a device without a real-time clock.

A TLS stack needs the time to check a certificate's validity period, and a device without a real-time clock has none until something tells it. Until then the clock has a floor, a time it is known not to be earlier than: when the library's source was built, or a time the application saved and set with kii_clock_set_floor(). Once a server states its time in a response to a kii_t the clock is set on with kii_set_clock(), or the application sets one with kii_clock_set_time(), the clock counts on from it with the monotonic clock.

So a check made before then has a lower bound of the time only: a certificate that expired before it is known to have expired, but one that is not valid until later cannot be told from one that is valid now. The same goes long after a time was given, 24 hours by default (kii_clock_set_exact_for()): a monotonic clock drifts, so what it counts is then a lower bound too. And if the monotonic clock goes back, the time given becomes the floor, until the next. A certificate refused as not valid yet while the clock had the time suggests the time fell behind: kii_clock_forget_time() makes it a lower bound until the next, so that the device connects again.

kii_clock_check_validity() applies that, for socket callbacks to use when checking the server's certificate, and kii_clock_get_time() gives the time and which of the two it is, for a TLS stack to check with itself.

Initialize with kii_clock_init(). The functions are safe to call from the socket callbacks, and from any task once kii_clock_set_cb_lock() has set a lock.
