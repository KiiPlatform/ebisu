Detailed Description

Tokens shared by the kii_t instances acting as the same thing.

Renews the access token when it is close to expiry or the server refuses it, the way it was obtained:

  • one onboarding obtained, by onboarding again through Thing-IF with the thing's credentials;
  • one a login or registration obtained, with the refresh token first, and by logging in with the thing's credentials when there is none or the server rejects it.

A request whose body was built in the buffer set by kii_set_buff() is then sent again; see kii_set_session().

Every kii_t acting as the thing must use the same session: a refresh invalidates the previous tokens, which would fail the requests of a kii_t holding its own copy, and sharing renews once for all of them.

Initialize with kii_session_init(), set the lock and the clock, then attach with kii_set_session().
