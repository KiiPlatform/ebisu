◆ EBISU_CB_LOCK

typedef void(* EBISU_CB_LOCK) (void *userdata)

Callback acquires or releases a lock.

Set in pairs, one acquiring and one releasing, by kii_session_set_cb_lock(). The lock need not be recursive.

While it is held, other tasks may be kept waiting for the length of an HTTP request, and the callbacks ebisu makes in between include the socket callbacks. A platform on which no other task using the same session can run while the lock is held – including inside those callbacks – may implement both as no-ops.

Parameters
[in]userdataContext object pointer.

◆ EBISU_CB_MONOTONIC_MS

typedef uint64_t(* EBISU_CB_MONOTONIC_MS) (void *userdata)

Callback returns a monotonic time in milliseconds.

The value must never decrease, and must not jump when the wall clock is changed, for example by NTP. It must keep counting while the device sleeps: a tick counter that stops in low-power modes has tokens renewed late, and ebisu_clock_t falling behind. Its origin is arbitrary; only differences are used. Platforms whose tick counter is 32 bits wide must extend it to 64, or it wraps after about 49.7 days.

Parameters
[in]userdataContext object pointer.
Returns
Milliseconds elapsed since an arbitrary, fixed origin.
