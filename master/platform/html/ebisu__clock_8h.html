typedef struct ebisu_clock_t ebisu_clock_t

The time of day, for a device without a real-time clock.

A TLS stack needs the time to check a certificate's validity period, and a device without a real-time clock has none until something tells it. Until then the clock has a floor, a time it is known not to be earlier than: when the library's source was built, or a time the application saved and set with ebisu_clock_set_floor(). Once a server states its time in a response to a kii_t the clock is set on with kii_set_clock(), or the application sets one with ebisu_clock_set_time(), the clock counts on from it with the monotonic clock.

So a check made before then has a lower bound of the time only: a certificate that expired before it is known to have expired, but one that is not valid until later cannot be told from one that is valid now. The same goes long after a time was given, 24 hours by default (ebisu_clock_set_exact_for()): a monotonic clock drifts, so what it counts is then a lower bound too. And if the monotonic clock goes back, the time given becomes the floor, until the next. A certificate refused as not valid yet while the clock had the time suggests the time fell behind: ebisu_clock_forget_time() makes it a lower bound until the next, so that the device connects again.

ebisu_clock_check_validity() applies that, for socket callbacks to use when checking the server's certificate, and ebisu_clock_get_time() gives the time and which of the two it is, for a TLS stack to check with itself.

Initialize with ebisu_clock_init(). The functions are safe to call from the socket callbacks, and from any task once ebisu_clock_set_lock() has set a lock.

◆ ebisu_clock_forget_time()

void ebisu_clock_forget_time ( ebisu_clock_t *  clock)

Forget the time, keeping what was counted as the floor.

For the socket callbacks to call when their TLS stack refuses the server's certificate as not valid yet, while the clock had the time. On a device whose monotonic clock stops while it sleeps, the time falls behind, and a server that renewed its certificate meanwhile presents one that starts after it. Without a time of the server's, the clock could not catch up: the connection that would bring one is refused. Forgotten, the time becomes a lower bound, which ebisu_clock_check_validity() and the socket callbacks do not refuse a certificate for not having started by, so the next connection goes through, and its response gives the clock the time again.

What was counted on, less 1%, becomes the floor: the time is at least that, however the monotonic clock ran.

[out]clockebisu_clock_t instance.

uint32_t  seconds

Set how long a time given stays exact.

For that long after it was given, the clock counts on from a time and gives the result as the time. After that, as a lower bound only, allowing for a monotonic clock running up to 1% fast: ebisu_clock_check_validity() then no longer tells a validity period that has not started. A kii_t the clock is set on gives it a time with every response, so this matters to a device that makes no HTTP requests for a long time, only MQTT ones.

Parameters
[out]clockebisu_clock_t instance.
[in]seconds24 hours by default. 0 never takes a time as exact.

Set the lock guarding the clock.

Needed when more than one task uses the clock, as when kii_t of different tasks are set on it. The monotonic clock is called only with it held.

The socket callbacks may use the clock while kii holds a session's lock, so this has to be a lock of its own, not a session's.
