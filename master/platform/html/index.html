platform

platform holds the ports: the abstractions of core, its sockets, system and locks, implemented for a kind of system each, from what that system provides.

Ports

Implementations for a kind of system, each a static library of its own, built where what it needs is found, which links libebisu_core. Link one with libebisu_tio, libebisu_kii or libebisu_khc.

  • POSIX (ebisu_posix.h, library ebisu_posix): ebisu_posix_system(), whose tasks are detached threads, whose delays are nanosleep() and whose monotonic clock is CLOCK_MONOTONIC, and ebisu_posix_lock_t, a pthread mutex. Needs POSIX threads.
  • OpenSSL (ebisu_openssl.h, library ebisu_openssl): ebisu_openssl_socket_t, TLS 1.2 or later over a blocking BSD socket, taking in TLS 1.2 only suites with forward secrecy and authenticated encryption, Mozilla's intermediate list, and checking the server's certificate at an ebisu_clock_t's time. It looks the host up with getaddrinfo() and tries each of its addresses, IPv6 and IPv4, both within its connect timeout. Its connections share one SSL_CTX: the system's CA certificates, or those of an ebisu_openssl_tls_t set up with a CA file or directory, for a device without the system's. The SSL_CTX keeps the TLS sessions of the last connections to a few hosts, and a connection offers the server the one for its host and port to resume, which saves most of the handshake when the server takes it. Its last_error says why an operation failed, which also goes to the logger set with ebisu_openssl_socket_set_logger(), or to stderr. Needs OpenSSL 1.0.2 or later, and POSIX threads.
  • Win32 (ebisu_win32.h, library ebisu_win32): ebisu_win32_system(), whose tasks are threads of their own, made with _beginthreadex(), whose delays are Sleep() and whose monotonic clock is GetTickCount64(), and ebisu_win32_lock_t, an SRWLOCK.
  • Schannel (ebisu_schannel.h, library ebisu_schannel): ebisu_schannel_socket_t, TLS over Winsock 2 with Schannel, through SSPI, checking the server's certificate itself with crypt32, at an ebisu_clock_t's time: a chain to a root in the Windows root store, valid for server authentication, issued for the host. It drives Schannel itself, keeping what it has received but not yet returned, and waits for a receive with select(), so that a timeout leaves the connection usable. Its last_error says why an operation failed, which also goes to the logger set with ebisu_schannel_socket_set_logger(), or to stderr. Needs only what Windows provides, ws2_32, secur32 and crypt32, which it links.

The Linux sample uses the POSIX and OpenSSL ports, and the Windows sample the Win32 and Schannel ones.

A daemon can send the OpenSSL port's diagnostics to syslog with a logger such as this one. vsyslog() isn't POSIX, but glibc, musl and the BSDs have it:

#include <ebisu_openssl.h>
#include <syslog.h>
static void to_syslog(ebisu_logger_t* self, ebisu_log_level_t level,
const char* fmt, va_list args)
{
static const int priorities[] = { LOG_ERR, LOG_WARNING, LOG_INFO, LOG_DEBUG };
vsyslog(priorities[level], fmt, args);
}
static const ebisu_logger_ops_t syslog_ops = { to_syslog };
static ebisu_logger_t syslog_logger = { &syslog_ops };
ebisu_openssl_socket_set_logger(&sock, &syslog_logger);
