platform

platform holds the ports: the abstractions of core, its sockets, system and locks, implemented for a kind of system each, from what that system provides. It also holds loggers, for where a port's diagnostics and an application's own messages go, and a probe of the name servers, for a lookup not to wait for ones that don't answer.

Ports

Implementations for a kind of system, each a static library of its own, built where what it needs is found, which links libebisu_core. Link one with libebisu_tio, libebisu_kii or libebisu_khc.

Each system also makes locks of its port's kind, for ebisu_system_lock_create(), so code given only the system can have one. The POSIX and Win32 systems take them from the heap, with malloc(). The FreeRTOS one takes them from FreeRTOS's heap, with configSUPPORT_DYNAMIC_ALLOCATION from V9 on, and makes none without it.

The POSIX and Win32 systems give the time of day as a clock too, for ebisu_system_clock(), the same one each time: the time the system has, which a TLS port checks the server's certificate at once set with its *_socket_set_clock(). One earlier than the library's source, a time the system has not set, is a lower bound, against which a certificate is refused only if it expired before it. FreeRTOS keeps no time of day, so its system gives the clock the application keeps and sets on it, if any: on a board without a real-time clock, an ebisu_server_clock_t, which takes the time servers state, or a time source of the application's gives it, or else a clock of the application's own, as the kii README describes.

  • POSIX (ebisu_posix.h, library ebisu_posix): ebisu_posix_system(), whose tasks are detached threads, whose delays are nanosleep() and whose monotonic clock is CLOCK_MONOTONIC, ebisu_posix_lock_t, a pthread mutex, and ebisu_posix_tcp_socket_t, plain TCP over a blocking BSD socket, for a server without TLS, as an MQTT broker's port is with kii_enable_insecure_mqtt(). Nothing it sends is encrypted. It looks the host up and connects as the OpenSSL port's socket does, with the same code, and a lookup thread of its own for a host and port. A send to a peer that has gone fails, with MSG_NOSIGNAL, or SO_NOSIGPIPE where send() has no such flag, rather than raise SIGPIPE. Its last_error says why an operation failed, which also goes to the logger set with ebisu_posix_tcp_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF, and its recv_wait waits with poll(). Needs POSIX threads.
  • OpenSSL (ebisu_openssl.h, library ebisu_openssl): ebisu_openssl_socket_t, TLS 1.2 or later over a blocking BSD socket, taking in TLS 1.2 only suites with forward secrecy and authenticated encryption, Mozilla's intermediate list, and checking the server's certificate at an ebisu_clock_t's time. It looks the host up with getaddrinfo() and tries each of its addresses, IPv6 and IPv4, both within its connect timeout. A lookup the timeout cuts short goes on on a thread of its own, which later connects to the same host and port wait for rather than look it up again. Its connections share one SSL_CTX: the system's CA certificates, or those of an ebisu_openssl_tls_t set up with a CA file or directory, for a device without the system's. The SSL_CTX keeps the TLS sessions of the last connections to a few hosts, and a connection offers the server the one for its host and port to resume, which saves most of the handshake when the server takes it. Its last_error says why an operation failed, which also goes to the logger set with ebisu_openssl_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF, and its recv_wait waits with poll(), after what OpenSSL has decrypted. ebisu_openssl_socket_get_protocol() and ebisu_openssl_socket_get_cipher() give the TLS version and cipher suite a connection negotiated, as OpenSSL names them. Needs OpenSSL 1.0.2 or later, and POSIX threads.
  • Win32 (ebisu_win32.h, library ebisu_win32): ebisu_win32_system(), whose tasks are threads of their own, made with _beginthreadex(), whose delays are Sleep() and whose monotonic clock is GetTickCount64(), ebisu_win32_lock_t, an SRWLOCK, and ebisu_win32_tcp_socket_t, plain TCP over Winsock 2, for a server without TLS. Nothing it sends is encrypted. It looks the host up and connects as the Schannel port's socket does, with the same code, and waits for a receive with select(), as it does too. Its last_error and logger are as the Schannel port's. Needs only what Windows provides, ws2_32, which it links.
  • Schannel (ebisu_schannel.h, library ebisu_schannel): ebisu_schannel_socket_t, TLS over Winsock 2 with Schannel, through SSPI, checking the server's certificate itself with crypt32, at an ebisu_clock_t's time: a chain to a root in the Windows root store, valid for server authentication, issued for the host. It looks the host up with GetAddrInfoExW() and tries each of its addresses, IPv6 and IPv4, both within its connect timeout, and cancels a lookup the timeout cuts short. It drives Schannel itself, keeping what it has received but not yet returned, and waits for a receive with select(), so that a timeout leaves the connection usable, as its recv_wait waits too. Its last_error says why an operation failed, which also goes to the logger set with ebisu_schannel_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF. ebisu_schannel_socket_get_protocol() and ebisu_schannel_socket_get_cipher() give the TLS version and cipher suite a connection negotiated, the suite by its standard name from Windows 10 on. Needs Windows 8 or later, and only what it provides, ws2_32, secur32 and crypt32, which it links.
  • FreeRTOS (ebisu_freertos.h, library ebisu_freertos): ebisu_freertos_system_t, whose tasks are FreeRTOS tasks of the stack depth and priority it is initialized with, made with xTaskCreate(), whose delays are vTaskDelay(), for at least the time asked for, whose monotonic clock is the tick count with the times it has overflowed, which doesn't wrap, and whose clock is the one the application sets with ebisu_freertos_system_set_clock(), and ebisu_freertos_lock_t, a FreeRTOS mutex, in the lock itself with configSUPPORT_STATIC_ALLOCATION, and waiting past portMAX_DELAY without INCLUDE_vTaskSuspend. Built where the application's CMake build has FreeRTOS-Kernel's own target, freertos_kernel, which adding the kernel's directory before ebisu's makes, with the application's FreeRTOSConfig.h, and not installed, as the kernel isn't. A kernel before V11, which has no CMake build of its own, is a library of its sources the application's build names freertos_kernel, as tests/freertos makes one, or a build without CMake compiles ebisu_freertos.c with the kernel. Needs FreeRTOS-Kernel V8.1.2 or later, configUSE_MUTEXES and INCLUDE_vTaskDelay, and for tasks INCLUDE_vTaskDelete and the heap, which a kernel before V9 makes everything from and V9 on with configSUPPORT_DYNAMIC_ALLOCATION, without which the system has none to make. With newlib, it needs configUSE_NEWLIB_REENTRANT too, but for jkii built with EBISU_NO_STRTOD: newlib's strtod(), which jkii reads doubles with, works in the calling task's newlib state, and the handler's and the updater's tasks parse JSON at once.
  • FreeRTOS-Plus-TCP (ebisu_freertos_tcp.h, library ebisu_freertos_tcp): ebisu_freertos_tcp_socket_t, plain TCP over FreeRTOS-Plus-TCP, for TLS over it with the mbedTLS port's socket, or for a server without TLS. Nothing it sends itself is encrypted. It connects to an address as written, IPv4, or IPv6 with ipconfigUSE_IPv6, or looks a name up with FreeRTOS_getaddrinfo(), IPv6 too with ipconfigUSE_IPv6, and tries each address within its connect timeout: the lookup takes as long as FreeRTOS-Plus-TCP's DNS client does. A receive that times out leaves the connection as it was, a peer that closes or resets it is the end of the stream, and recv_wait waits with a receive that peeks. Its last_error says why an operation failed, with FreeRTOS-Plus-TCP's error, which also goes to the logger set with ebisu_freertos_tcp_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF. ebisu_freertos_tcp_dns() has FreeRTOS-Plus-TCP's name servers for the DNS probe, below. Built where the application's build has FreeRTOS-Plus-TCP's own target, freertos_plus_tcp, as well as the kernel's, with its FreeRTOSIPConfig.h, and not installed. Needs FreeRTOS-Plus-TCP V4.2 or later, that of FreeRTOS LTS 202406, ipconfigUSE_TCP and ipconfigUSE_DNS.
  • lwIP (ebisu_lwip.h, library ebisu_lwip): ebisu_lwip_tcp_socket_t, plain TCP over lwIP's sockets, the TCP/IP stack of many vendors' SDKs, for TLS over it with the mbedTLS port's socket, or for a server without TLS. Nothing it sends itself is encrypted. It looks the host up with lwip_getaddrinfo(), which takes an address as written as it is, and gives a name's first address only, of the family LWIP_DNS_ADDRTYPE_DEFAULT puts first, which it connects to without blocking, within its connect timeout: the lookup takes as long as lwIP's DNS client does. A receive that times out leaves the connection as it was, a peer that closes it is the end of the stream and one that resets it a failure, but for lwIP 2.0, whose receive takes a reset for the end of the stream too. It waits for a connection and for recv_wait with lwip_select(), or lwip_poll() where lwIP 2.1 or later is built without select, and sets its timeouts as lwIP takes them: an int of milliseconds in lwIP 1.4, and as LWIP_SO_SNDRCVTIMEO_NONSTANDARD says from 2.0 on. Keepalive and TCP_NODELAY are as the POSIX socket's, below. Its last_error says why an operation failed, with lwIP's errno, or lwip_getaddrinfo()'s error for a lookup, which also goes to the logger set with ebisu_lwip_tcp_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF. ebisu_lwip_dns() has the name servers lwIP's DNS client asks, for the DNS probe, below. Built where the application's build has lwIP's core target, lwipcore, as including lwIP's src/Filelists.cmake makes it from 2.1 on, with lwIP's include directories and definitions in LWIP_INCLUDE_DIRS and LWIP_DEFINITIONS, as lwIP's CMake takes them, and not installed: lwIP 1.4's include directories are its src/include and src/include/ipv4. A build without CMake, as many vendors' SDKs are, compiles ebisu_lwip_tcp.c with lwIP's headers and the application's lwipopts.h. Needs lwIP 1.4.1 or later, with an OS, NO_SYS at 0, LWIP_SOCKET, LWIP_TCP, LWIP_DNS, LWIP_SO_RCVTIMEO and LWIP_SO_SNDTIMEO, and an errno of each task's own where more than one task uses sockets, as newlib's is with FreeRTOS's configUSE_NEWLIB_REENTRANT, but for lwIP 1.4 built without ERRNO and lwIP 2.0 built with LWIP_SOCKET_SET_ERRNO at 0, which set no errno: there the socket reads each socket's own error, with SO_ERROR.
  • mbedTLS (ebisu_mbedtls.h, library ebisu_mbedtls): ebisu_mbedtls_socket_t, TLS 1.2 or later, 1.3 where mbedTLS has it, with mbedTLS 3.6 or 4.x, or mbedTLS 2 from 2.4, as vendors' SDKs ship it, with TLS 1.2 at the most, over another socket of the system's, of plain TCP, which connects, sends and receives the records, and whose timeouts are the connection's: the POSIX port's ebisu_posix_tcp_socket_t, the Win32 port's, or one over a microcontroller's TCP/IP stack. Its connections share an ebisu_mbedtls_tls_t: the CA certificates the server's has to chain to, PEM or DER, from memory, and mbedTLS's configuration, which ebisu_mbedtls_tls_config() gives the application for settings of its own, such as the cipher suites. It checks the server's certificate chain and host name, and each certificate's dates at an ebisu_clock_t's time, in place of mbedTLS's own check at the system's, or at the system's time without one, as mbedTLS has it with MBEDTLS_HAVE_TIME_DATE: a device without a real-time clock connects with the clock alone. Random numbers come from PSA's generator, which ebisu_mbedtls_tls_init() starts, from mbedTLS's entropy sources, or with mbedTLS 2 from a CTR_DRBG of the configuration's, seeded from them, but for an mbedTLS 2 built without MBEDTLS_CTR_DRBG_C or MBEDTLS_ENTROPY_C, as some of vendors' SDKs configure it, where EBISU_MBEDTLS_SETS_RNG is 0 and the application sets the generator, a cryptographically secure one, with mbedtls_ssl_conf_rng() on ebisu_mbedtls_tls_config(): TLS's keys are made from it. A receive that times out leaves the connection as it was, and recv_wait counts what mbedTLS has and hasn't returned. Its last_error says why an operation failed: what the socket under it said, for what failed there, a certificate refused, with mbedTLS's verify flags, or another TLS failure, with mbedTLS's error, which also goes to the logger set with ebisu_mbedtls_socket_set_logger(), if any, unless it is built with -DEBISU_LOG=OFF. ebisu_mbedtls_socket_get_protocol() and ebisu_mbedtls_socket_get_cipher() give the TLS version and cipher suite a connection negotiated, as mbedTLS names them. Built where CMake finds mbedTLS: the application's, added before ebisu's, or one installed, as its CMake package has it, both MbedTLS::mbedtls, which an application with mbedTLS 2, which has no CMake package, names its libraries itself. Sockets of a configuration on more than one task at once need mbedTLS built with MBEDTLS_THREADING_C. mbedTLS 2 is past its end of life: its last release, 2.28.10, came in March 2025, and an earlier one lacks the fixes since it. The port takes the one an SDK ships all the same. An application whose mbedTLS is built with a record smaller than the 16 KB a server may send asks the server for less with mbedtls_ssl_conf_max_frag_len(), through ebisu_mbedtls_tls_config(), which a server that doesn't take the extension ignores.
  • PolarSSL, experimental (ebisu_polarssl.h, library ebisu_polarssl): ebisu_polarssl_socket_t, the mbedTLS port's socket for PolarSSL 1.3, from 1.3.8, and mbedTLS 1.3, to its last release, 1.3.22, which kept PolarSSL's API: for vendors' SDKs that ship it, some with its cryptography in their chips' ROM. TLS 1.2, over another socket of the system's, as the mbedTLS port's, with the same checks of the server's certificate, the clock's dates among them, or the system's with POLARSSL_HAVE_TIME, the same last_error, logger and recv_wait. PolarSSL 1.3 has no configuration connections share: the ebisu_polarssl_tls_t keeps the CA certificates, the verification and a CTR_DRBG of its own, seeded from PolarSSL's entropy sources, and sets each connection's context from them as it connects, then calls the application's setup, set with ebisu_polarssl_tls_set_setup(), for settings of its own, such as the cipher suites or the maximum fragment length, and the random generator, a cryptographically secure one, where PolarSSL is built without POLARSSL_CTR_DRBG_C or POLARSSL_ENTROPY_C and EBISU_POLARSSL_SETS_RNG is 0. Built where CMake finds PolarSSL as PolarSSL::polarssl, which an application names its library, as tests/polarssl/install_polarssl.sh writes a package that does. Sockets of a configuration on more than one task at once need PolarSSL built with POLARSSL_THREADING_C, which the port locks its CTR_DRBG with, as PolarSSL's has no lock of its own. Experimental: its API may change. PolarSSL 1.3 is past its end of life: its last release, 1.3.22, came in February 2018, and 1.3.8, of July 2014, lacks the security fixes of each of the 14 since, among them that of 1.3.21 for an authentication bypass with optional verification, which the port, which requires it, doesn't take the path of. Use the mbedTLS port where mbedTLS 2.4 or later can be had.

Servers whose certificates no CA issued

The TLS ports check the server's certificate in full: a chain to a CA certificate trusted, in date, issued for the host connected to. A server on a local network often has a certificate it made itself, or one of a private CA that doesn't name the address it's reached at. For those, a configuration can check less, as ebisu_tls_verify_t in ebisu_socket.h has it, with ebisu_openssl_tls_set_verify(), ebisu_mbedtls_tls_set_verify() and, on a socket, ebisu_schannel_socket_set_verify():

  • EBISU_TLS_VERIFY_CHAIN: the chain and the dates, not the name.
  • EBISU_TLS_VERIFY_PIN: the SHA-256 of the certificate, or of its public key, known beforehand; nothing else. A pin of the public key stays the same when the server makes a new certificate for the same key.
  • EBISU_TLS_VERIFY_NONE: nothing. The connection is encrypted, but whoever answers for the address is taken for the server, and each connection logs a warning that it wasn't verified.

Each is asked for; none is a default, and the configuration that sockets without one share is always checked in full. A pin is computed from the server's certificate with the openssl command:

# Of the certificate:
openssl x509 -in server.pem -outform der | openssl dgst -sha256
# Of its public key:
openssl x509 -in server.pem -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256
#include <ebisu_openssl.h>
static ebisu_openssl_tls_t tls;
static ebisu_openssl_socket_t sock;
/* The server's public key's SHA-256, as the second command prints it. */
static const unsigned char pin[EBISU_TLS_PIN_SIZE] = { 0x5c, 0x1f, /* ... */ };
if (!ebisu_openssl_tls_init(&tls, NULL, NULL) ||
!ebisu_openssl_tls_set_verify(&tls, EBISU_TLS_VERIFY_PIN, pin)) {
/* OpenSSL failed, or memory ran out. */
}

Connections held for long

A connection held open for hours, with a small request now and then, meets two things TCP does by default. A peer that went away, by losing power or through a NAT on the way dropping the idle connection's entry, is noticed only when the next request goes unanswered. And Nagle's algorithm holds a small segment back while an earlier one is unacknowledged, so a request written in two pieces can wait for the first's ACK.

Each TCP socket of the ports can ask for keepalive and for TCP_NODELAY, neither of which it has unless asked. Both apply from the next connect:

Keepalive takes the seconds idle before the first probe, the seconds between probes and the count of probes unanswered before the connection is given up, 0 leaving the last two to the system: SO_KEEPALIVE, with TCP_KEEPIDLE (TCP_KEEPALIVE on macOS), TCP_KEEPINTVL and TCP_KEEPCNT. Windows takes them from Windows 10, version 1709. A peer that has gone is noticed within about idle + interval × count seconds of the connection going idle: a send or a receive then fails. An option the system can't set, or a value it refuses, is said at EBISU_LOG_WARNING to the socket's logger, and the connection made without it. lwIP takes the idle time, interval and count with LWIP_TCP_KEEPALIVE; without it, it probes after its defaults, 2 hours, then every 75 seconds, 9 times, which the socket says.

The mbedTLS port's socket goes over another, whose options these are. FreeRTOS-Plus-TCP has neither per socket. It sends keepalive probes on every connection when FreeRTOSIPConfig.h sets ipconfigTCP_KEEP_ALIVE to 1, with ipconfigTCP_KEEP_ALIVE_INTERVAL seconds between them. With its sliding windows, ipconfigUSE_TCP_WIN at 1 as by default, it has no Nagle's algorithm: a small segment goes as soon as the peer's window has room, unless a socket asks for full-size ones with FREERTOS_SO_SET_FULL_SIZE, which ebisu_freertos_tcp_socket_t doesn't. Without them, one segment is unacknowledged at a time, so a request in two pieces waits for the first's ACK all the same.

Loggers

ebisu_loggers.h, library ebisu_loggers, built on POSIX and on Windows, has loggers that take a port's diagnostics, or an application's own messages through core's ebisu_log(). Each has a level, the least important it writes, and drops what matters less, so a port can be given one at EBISU_LOG_DEBUG and another at EBISU_LOG_ERROR together, through core's ebisu_log_fanout_t. Each may be called from more than one task at once, and cuts a message longer than EBISU_LOGGER_LINE_MAX, 1024 bytes, short with ....

Nothing in ebisu logs until it is given a logger, the ports included, and ebisu_log() drops a message given none. To see a port's failures on stderr, give it an ebisu_stdio_logger_t on stderr at EBISU_LOG_WARNING.

  • To a stdio stream (ebisu_stdio_logger_t): a line of the level and the message, as in error: failed to connect to example.com., to stderr or a file, written with one call and flushed.
  • To a file kept under a size (ebisu_file_logger_t): the same lines, to a file at a path. When a line would take it past its size, the file is renamed to its path with .1 after it, which replaces the one there, and a new one started, so that a device's flash holds at most twice the size, and the last of the log. The line is formatted before the lock it is given is taken, and written, counted and the file renamed under it. With ebisu_file_logger_set_timestamps(), each line starts with the system's time of day, in UTC to the millisecond, as RFC 3339 has it, as in 2026-11-15T07:46:05.123Z error: failed to connect to example.com., taken under the lock, so that a file's times are in the order of its lines.
  • To syslog (ebisu_syslog_logger_t, on POSIX): syslog(), with a facility and the severity of the level. openlog() is the application's to call, if it wants to.
  • To a syslog server over UDP (ebisu_syslog_udp_logger_t): a datagram for each message, formatted as RFC 5424 says, with the time to the millisecond, the host's name, the application's and the process's identifier, and sent as RFC 5426 does, to an IPv4 or IPv6 server looked up once, when the logger is initialized. The host's name can be another than the system's, such as a device's serial number, for a server to tell devices apart that all have the same. Sending never waits: what the socket can't take at once is dropped, as is what the network loses.

The loggers' levels and the fan-out's array are set before they are used, and don't change. Core's ebisu_log_level_filter_t wraps any logger in a level that can change while it logs, as from a server's configuration, which ebisu_log_level_parse() reads the name of. DNS probe

ebisu_dns_probe.h, library ebisu_dns_probe, asks whether the name servers answer before a host is looked up. getaddrinfo() can't be given a timeout: when the servers don't answer, a lookup waits for as long as the C library keeps asking them again, and so does the task that looked up: how long is below.

The probe needs nothing of the system's itself: it asks the name servers an ebisu_dns_t of core's lists, as that has them asked. The POSIX, Win32, FreeRTOS-Plus-TCP and lwIP ports have the system's:

  • ebisu_posix_dns(): the servers of /etc/resolv.conf, as the C libraries read it, or 127.0.0.1 without one, asked over BSD sockets;
  • ebisu_win32_dns(): those of the network adapters that are up, as GetAdaptersAddresses() lists them, but the placeholders fec0:0:0:ffff::1 to ::3, which Windows lists for an adapter without an IPv6 server, asked over Winsock. Without any, none is.
  • ebisu_freertos_tcp_dns(): those FreeRTOS-Plus-TCP's DNS client asks, in the order it asks them: of the family it prefers, those of the first end-point that has one, from the one the next lookup asks, as DHCP, RA or the application set them, asked over a UDP socket of FreeRTOS-Plus-TCP's. ICMP's port unreachable doesn't reach that socket, so a server nothing listens on doesn't answer in time, rather than refuse.
  • ebisu_lwip_dns(): those lwIP's DNS client asks, in the order it asks them: the first of dns_getserver()'s, and each next while it is set, as DHCP, RA or dns_setserver() set them, asked over a UDP socket of lwIP's. lwIP tells that socket nothing of ICMP's port unreachable, so a server nothing listens on doesn't answer in time, rather than refuse.

An application on another system implements the two operations that matter, servers and ask, and the probe works there too.

ebisu_dns_probe() sends one query for the host to each of the first 3 servers in turn, until one answers, giving each the time it is given. ebisu_dns_probe_servers() asks the servers it is given instead. Any answer counts, that the name doesn't exist too: the probe tells only whether a server answers. A host that needs no server, an address or localhost, needs no probe.

ebisu_dns_probe_socket_t probes before another socket connects, and fails the connect if no server answers, with EBISU_SOCK_ERROR_DNS, rather than have the other socket look the host up. The rest is the other socket's, which may be any: the OpenSSL, Schannel or mbedTLS port's, or the POSIX, Win32, FreeRTOS-Plus-TCP or lwIP port's of plain TCP.

#include <ebisu_dns_probe.h>

How long a lookup waits

When the name servers don't answer, a lookup ends when the C library gives up on them. The UDP logger's init waits that long, and the thread for a host and port of the OpenSSL port, or of the POSIX port's plain socket, lasts that long. Timed with servers that never answer, and /etc/resolv.conf's default options:

Servers glibc 2.26, 2.39 musl 1.1.24, 1.2.5
1 10 s 5 s
3 28 s 5 s
3, and 2 search domains 56 s 5 s

glibc asks the servers one after the other, and a search list makes it ask them again. musl asks them all at once, and gives up after its timeout.

options timeout:1 attempts:1 in /etc/resolv.conf makes the wait 1 second for one server, with either library, for every program on the system. glibc also reads options from the environment variable RES_OPTIONS, for one program: RES_OPTIONS="timeout:1 attempts:1" makes three servers' wait 3 seconds. musl doesn't read it, and glibc ignores it for a program that runs with more than its user's privileges: setuid, setgid, or given file capabilities, such as cap_net_bind_service. A shorter timeout fails a lookup whose server takes longer to answer, as one over a slow link can.

With another source after dns on the hosts: line of /etc/nsswitch.conf, as myhostname or files, glibc goes on to it when the servers don't answer. The lookup then fails as for a name that doesn't exist, EAI_NONAME, where without one it fails with EAI_AGAIN.

On Windows Server 2025, a lookup whose one server never answered ended after 12 seconds, and failed as for a name that doesn't exist, WSAHOST_NOT_FOUND. The connect timeout of the Schannel port, or of the Win32 port's plain socket, cuts it short: the lookup is cancelled, and the connect fails with EBISU_SOCK_ERROR_TIMEOUT.

FreeRTOS-Plus-TCP's DNS client asks one server at a time, ipconfigDNS_REQUEST_ATTEMPTS times, 5 by default, each waiting ipconfigDNS_RECEIVE_BLOCK_TIME_TICKS, 5 seconds by default, and goes on to the end-point's next server after each that doesn't answer. In QEMU, with the defaults and a server that never answered, a lookup ended after 25 seconds. It fails with pdFREERTOS_ERRNO_ENOENT, as for a name that doesn't exist. With ipconfigUSE_IPv6, the plain socket looks a name up for IPv6 too, after IPv4: twice that. Its connect timeout doesn't cut a lookup short.

lwIP's DNS client asks one server at a time: DNS_MAX_RETRIES queries, 4 by default, at once and then 1, 2 and 4 seconds in, as DNS_TMR_INTERVAL's second counts, and gives up on it 3 seconds after the last, 7 seconds in all. It then goes on to the next of DNS_MAX_SERVERS, 2 by default, while it is set. Each lookup starts again from the first, so one that doesn't answer costs every lookup its time. On the host, with servers that never answered, a lookup ended after 7 seconds for one and 14 for two, with lwIP 2.0.2 to 2.2.1 alike, and failed with EAI_FAIL. A lower DNS_MAX_RETRIES in lwipopts.h shortens it, for every lookup: at 2, a server has 2 seconds, with one query sent again. lwIP's cache answers a name it has kept, for as long as its answer's TTL, up to a week, with no server at all. The lwIP socket's connect timeout doesn't cut a lookup short.
