A lock that is a FreeRTOS mutex.

With priority inheritance, as FreeRTOS's mutexes have it, and not recursive. Waits for as long as the mutex is held, with or without INCLUDE_vTaskSuspend. Needs configUSE_MUTEXES.

Initialize with ebisu_freertos_lock_init().

◆ ebisu_freertos_system_t

typedef struct ebisu_freertos_system_t ebisu_freertos_system_t

The system on FreeRTOS.

Each task is a FreeRTOS task of its own, of the stack depth and priority the system is initialized with, made with xTaskCreate(), which deletes itself when it ends. Making one takes from FreeRTOS's heap what xTaskCreate() does, and a few bytes more, given back as the task starts: it needs configSUPPORT_DYNAMIC_ALLOCATION, without which the system makes no tasks, and a heap that frees, as heap_1 doesn't, for a task that ends and starts again, as the MQTT task does when kii_start_push_task() is called again.

A delay is vTaskDelay(), for at least the time asked for, and none, for a delay of 0, a yield to the tasks of the same priority.

The monotonic clock is FreeRTOS's tick count, with the times it has overflowed, in milliseconds: it doesn't wrap. It counts while the device sleeps as far as the tick count does: with tickless idle, which steps the tick count on waking, but not through a sleep that stops the tick's timer which the port doesn't make up for. Called from tasks, or before the scheduler starts, not from interrupts.

Its locks, from ebisu_system_lock_create(), are ebisu_freertos_lock_t's from FreeRTOS's heap, with their mutexes in them with configSUPPORT_STATIC_ALLOCATION. Without configSUPPORT_DYNAMIC_ALLOCATION it makes none, and ebisu_system_lock_create() gives NULL.

FreeRTOS keeps no time of day, so the system's clock, ebisu_system_clock()'s, is the one the application keeps and sets with ebisu_freertos_system_set_clock(), and none until then.

Initialize with ebisu_freertos_system_init().

void ebisu_freertos_system_set_clock ( ebisu_freertos_system_t * system,
ebisu_clock_t * clock )

Set the clock the system gives, as ebisu_system_clock().

FreeRTOS keeps no time of day, so the system gives the one the application keeps, for code given only the system to find:

  • an ebisu_server_clock_t over this system, for a board without a real-time clock: the time servers state over TLS, or a time source of the application's gives it, counted on with the tick count;
  • or a clock of the application's own, implementing ebisu_clock_ops_t over a board's real-time clock, with ebisu_clock_from_system_time(), or over a time source of its own, an NTP client that authenticates its servers for instance, which may keep the time it is given in an ebisu_server_clock_t. The kii README's section on the time shows one.

ebisu itself never asks the system for its clock: set the clock on the sockets, and a clock that takes the time servers state on each kii_t, too. Set it before tasks other than the caller's may ask for it: the system doesn't guard it.

Parameters
[out]systemThe system.
[in]clockThe clock, which has to outlive the system's use of it; or NULL for none, as the system has until this sets one.
