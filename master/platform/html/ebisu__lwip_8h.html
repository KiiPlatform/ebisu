A TCP connection over lwIP's sockets, without TLS.

For TLS over it, with ebisu_mbedtls_socket_t, whose records it sends and receives, or for a server that takes plain TCP, such as the MQTT broker's port without TLS, which kii_enable_insecure_mqtt() connects to. Nothing it sends or receives itself is encrypted or authenticated.

It looks the host up with lwip_getaddrinfo(), which takes an address as written as it is, and gives a name's first address only, of the family LWIP_DNS_ADDRTYPE_DEFAULT puts first: that one address is what it connects to. A lookup takes as long as lwIP's DNS client does, as DNS_MAX_RETRIES and DNS_TMR_INTERVAL have it. Connecting takes the connect timeout at the most: see ebisu_lwip_tcp_socket_set_connect_timeout(). It connects without blocking, and waits for the connection with lwip_select(), or lwip_poll() where lwIP is built without select.

Its receive and send timeouts are SO_RCVTIMEO and SO_SNDTIMEO. A receive that times out is EBISU_SOCK_FAIL, which recv_timed_out tells from a lost connection, and leaves the connection as it was. A peer that closes the connection is the end of the stream, and one that resets it a failure, as a send to a peer that has gone is: but for lwIP 2.0's receive, which takes a reset for the end of the stream too, and leaves a send after it to fail. recv_wait waits with lwip_select() or lwip_poll().

Why an operation failed, its last_error says: a host that didn't resolve, with lwip_getaddrinfo()'s EAI_ error, an address that refused, a timeout, a peer that has gone, or another failure, each with lwIP's errno. It also goes to the logger set by ebisu_lwip_tcp_socket_set_logger(), if any.

One serves one connection at a time, from one task at a time, and is used again for the next once closed. Needs lwIP 2.0.2 or later, with an OS, NO_SYS 0, and LWIP_SOCKET, LWIP_TCP, LWIP_DNS, LWIP_SO_RCVTIMEO and LWIP_SO_SNDTIMEO. lwIP's sockets say why a call failed in errno, which has to be each task's own where more than one task makes them, as newlib's is with FreeRTOS's configUSE_NEWLIB_REENTRANT. Initialize with ebisu_lwip_tcp_socket_init().

unsigned int idle_s,
unsigned int interval_s,
unsigned int count )

Sets whether TCP checks an idle connection is still there.

With keepalive, TCP probes a connection that has been idle for idle_s seconds, and gives the connection up when count probes, interval_s seconds apart, go unanswered: a send or a receive on it then fails, rather than the next request finding out. So a peer that lost power, or a NAT that dropped the connection's entry, is noticed within about idle_s + interval_s * count seconds of the connection going idle.

It applies from the next connect: SO_KEEPALIVE, and TCP_KEEPIDLE, TCP_KEEPINTVL and TCP_KEEPCNT where lwIP is built with LWIP_TCP_KEEPALIVE. Without it, lwIP probes after TCP_KEEPIDLE_DEFAULT, every TCP_KEEPINTVL_DEFAULT, TCP_KEEPCNT_DEFAULT times, 2 hours, 75 seconds and 9 by default, and the socket says at EBISU_LOG_WARNING that it can't set them. So does it of a value lwIP refuses, and connects without it.

Parameters
[out]sockThe socket.
[in]idle_sSeconds idle before the first probe, or 0 for no keepalive, as the socket starts.
[in]interval_sSeconds between probes, or 0 for lwIP's.
[in]countProbes unanswered before the connection is given up, or 0 for lwIP's.

void ebisu_lwip_tcp_socket_set_logger ( ebisu_lwip_tcp_socket_t * sock,
ebisu_logger_t * logger )

Sets where the socket's diagnostics go.

Why an operation failed, at EBISU_LOG_ERROR: a host that didn't resolve or connect, a send or a receive that failed. A receive that times out isn't one. An option lwIP refuses, at EBISU_LOG_WARNING.

Built with EBISU_NO_LOG, as -DEBISU_LOG=OFF builds it, the socket logs nothing.

Parameters
[out]sockThe socket.
[in]loggerThe logger, which has to outlive the socket, or NULL, as the socket starts, for the diagnostics to go nowhere.

void ebisu_lwip_tcp_socket_set_nodelay ( ebisu_lwip_tcp_socket_t * sock,
bool nodelay )

Sets whether what is sent goes at once, with TCP_NODELAY.

Without it, as the socket starts, Nagle's algorithm holds a small segment back while an earlier one is unacknowledged: a request sent in two pieces can wait for the first's ACK, which a peer may delay. It applies from the next connect.

Parameters
[out]sockThe socket.
[in]nodelaytrue to send at once.
