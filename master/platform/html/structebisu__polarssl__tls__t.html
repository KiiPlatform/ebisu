Detailed Description

The TLS configuration connections share.

TLS 1.2, with PolarSSL's default cipher suites, which a server picks one of. The server's certificate has to chain to one of the configuration's CA certificates, and be issued for the host connected to, unless ebisu_polarssl_tls_set_verify() says otherwise. PolarSSL 1.3 has no configuration shared by connections, as mbedTLS 2 on has: the port keeps this one, and sets each connection's context from it as it connects.

Random numbers come from a CTR_DRBG of the configuration's own, which ebisu_polarssl_tls_init() seeds from PolarSSL's entropy sources, the hardware's with POLARSSL_ENTROPY_HARDWARE_ALT. PolarSSL built without POLARSSL_CTR_DRBG_C or POLARSSL_ENTROPY_C, as some of vendors' SDKs configure it, has neither, and EBISU_POLARSSL_SETS_RNG is 0: the application sets the generator, with ssl_set_rng() in its setup, which ebisu_polarssl_tls_set_setup() sets, and a connection fails without one. TLS's keys are made from these numbers, whichever gives them: the entropy sources have to give true randomness, and the application's generator has to be cryptographically secure, a hardware random number generator's, or a DRBG seeded from one. Connections share the generator: on more than one task at once, PolarSSL has to be built with POLARSSL_THREADING_C, with POLARSSL_THREADING_PTHREAD on POSIX, or POLARSSL_THREADING_ALT and functions of the system's, which the port locks its CTR_DRBG with, as PolarSSL's own doesn't; or the application's generator has to take calls from more than one task at once.

Initialize with ebisu_polarssl_tls_init(), before the connections, and free with ebisu_polarssl_tls_free() once none is open.
