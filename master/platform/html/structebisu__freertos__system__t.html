Detailed Description

The system on FreeRTOS.

Each task is a FreeRTOS task of its own, of the stack depth and priority the system is initialized with, made with xTaskCreate(), which deletes itself when it ends. Making one takes from FreeRTOS's heap what xTaskCreate() does, and a few bytes more, given back as the task starts: it needs EBISU_FREERTOS_DYNAMIC_ALLOCATION, without which the system makes no tasks, and a heap that frees, as heap_1 doesn't, for a task that ends and starts again, as the MQTT task does when kii_start_push_task() is called again.

A delay is vTaskDelay(), for at least the time asked for, and none, for a delay of 0, a yield to the tasks of the same priority.

The monotonic clock is FreeRTOS's tick count, with the times it has overflowed, in milliseconds: it doesn't wrap. It counts while the device sleeps as far as the tick count does: with tickless idle, which steps the tick count on waking, but not through a sleep that stops the tick's timer which the port doesn't make up for. Called from tasks, or before the scheduler starts, not from interrupts.

Its locks, from ebisu_system_lock_create(), are ebisu_freertos_lock_t's from FreeRTOS's heap, with their mutexes in them with EBISU_FREERTOS_STATIC_ALLOCATION. Without EBISU_FREERTOS_DYNAMIC_ALLOCATION it makes none, and ebisu_system_lock_create() gives NULL.

FreeRTOS keeps no time of day, so the system's clock, ebisu_system_clock()'s, is the one the application keeps and sets with ebisu_freertos_system_set_clock(), and none until then.

Initialize with ebisu_freertos_system_init().
