typedef bool(* KHC_CB_CONTINUE) (void *userdata)

Callback deciding whether a request goes on.

Called between the steps of khc_perform(khc*), each a socket operation or a callback, so that another task can cancel a request: the implementation reads a flag that task sets, under whatever lock their system has.

Parameters
[in,out]userdatacontext data passed to khc_set_cb_continue(khc*, KHC_CB_CONTINUE, void*).
Returns
true to go on, false to cancel the request: khc_perform(khc*) closes the connection, if one is open, and returns KHC_ERR_CANCELLED.

◆ khc_get_resp_date()

int64_t khc_get_resp_date ( khc *  khc)

Get the server's time, from the response's Date header.

Servers state their time, to the second, in their responses. A device without a real-time clock can take its time from there, to put timestamps in what it reports for instance, or to check the validity of certificates once it has talked to the server. The time is as trustworthy as the connection it came through, so the socket callbacks must verify the server's certificate.

The three forms of RFC 9110, section 5.6.7, are taken: the one servers must send, "Sun, 06 Nov 1994 08:49:37 GMT", and the obsolete RFC 850 and asctime() ones, "Sunday, 06-Nov-94 08:49:37 GMT" and "Sun Nov 6 08:49:37 1994". UTC is taken for GMT. RFC 850's two-digit year is read as RFC 9110 asks, against the year the library's source dates from. Anything else counts as no Date header, and so does a response with several that disagree or one in another form, or a date earlier than the source of the library, which no server running properly can send.

The date is cleared when khc_perform(khc*) starts, at each response's status line, so that an interim 1xx response's never stands for the final one's, and by khc_reset_except_cb(khc*) and khc_reset_except_request(khc*). It is when the server sent the response: read it right after khc_perform(khc*), and count from there with the device's own clock.

Parameters
[in]khcinstance.
Returns
Seconds since 1970-01-01T00:00:00Z when the response had a Date header, -1 otherwise.

Prepare to perform the same request again.

◆ khc_set_req_body_length()

void khc_set_req_body_length ( khc *  khc,
size_t  length 
)

Set the length of the request body.

With the length known, the body is sent with a Content-Length header rather than chunked, which some intermediaries handle poorly. The read callback set by khc_set_cb_read(khc*, KHC_CB_READ, void*) is asked for no more than is left of it, and has to give all of it: returning 0 before then fails the request with KHC_ERR_READ_CALLBACK, as the server would wait for the rest.

khc_reset_except_cb(khc*) sets it back to KHC_REQ_BODY_LENGTH_UNKNOWN, and khc_reset_except_request(khc*) keeps it, as part of the request.

Parameters
[out]khcinstance.
[in]lengthThe body's length in bytes, or KHC_REQ_BODY_LENGTH_UNKNOWN to send it chunked, as by default.

Set response header buffer pointer used by KHC_CB_HEADER. If this method is not called or set NULL to the buffer, khc allocates memory of response header buffer when the HTTP session started and free when the HTTP session ends. The buffer allocated by the khc is 256 bytes.

The buffer is used to store single HTTP response header. If header is larger than the buffer, the header is skipped and KHC_CB_HEADER is not called, which khc_get_resp_header_skipped(khc*) tells. khc needs to parse Status Line, Content-Length, Transfer-Encoding header to process HTTP message. The buffer must have enough size to store those headers: khc_perform(khc*) returns KHC_ERR_TOO_LARGE_DATA if it doesn't. 256 bytes would be enough. If you set the buffer by the method, the method must be called befor khc_perform(khc*) and memory used by the buffer can be safely freed after khc_perform(khc*) returned.

Set stream buffer.

Set stream buffer pointer used by KHC_CB_READ, KHC_CB_WRITE. If this method is not called or set NULL to the buffer, khc allocates memory of stream buffer when the HTTP session started and free when the HTTP session ends. The buffer allocated by khc is 1024 bytes.

The request body is sent a buffer at a time, in one write each: over TLS, at least one record each. 1024 bytes suit bodies of a few KB. For larger ones, on a slow or metered link, 4096 bytes or more send fewer, larger records, and responses are read in larger pieces too. A chunked body needs room for a chunk's size line and CRLF besides its data, a few bytes: with no room for data, khc_perform(khc*) returns KHC_ERR_TOO_LARGE_DATA. If you set the buffer by the method, the method must be called befor khc_perform(khc*) and memory used by the buffer can be safely freed after khc_perform(khc*) returned.

Set how long a request may take.

From the start of khc_perform(khc*) to the end of the response. Once it has passed, khc_perform(khc*) closes the connection, if one is open, and returns KHC_ERR_TIMEOUT. It is checked between steps, so a socket operation that blocks runs to its own timeout first: it bounds a response that trickles in through receives that each end in time, or a slow handshake made of many.

It needs the monotonic_ms of the system set by khc_set_system(khc*, ebisu_system_t*): without one, khc_perform(khc*) returns KHC_ERR_FAIL without connecting. khc_init(khc*) sets none, and the resets leave it.
