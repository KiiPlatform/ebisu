typedef bool(* KHC_CB_CONTINUE) (void *userdata)

Callback deciding whether a request goes on.

Called between the steps of khc_perform(khc_t*), each a socket operation or a callback, so that another task can cancel a request: the implementation reads a flag that task sets, under whatever lock their system has.

Parameters
[in,out]userdatacontext data passed to khc_set_cb_continue(khc_t*, KHC_CB_CONTINUE, void*).
Returns
true to go on, false to cancel the request: khc_perform(khc_t*) closes the connection, if one is open, and returns KHC_ERR_CANCELLED.

◆ khc_get_resp_date()

int64_t khc_get_resp_date ( khc_t * khc)

Get the server's time, from the response's Date header.

Servers state their time, to the second, in their responses. A device without a real-time clock can take its time from there, to put timestamps in what it reports for instance, or to check the validity of certificates once it has talked to the server. The time is as trustworthy as the connection it came through, so the socket callbacks must verify the server's certificate.

The three forms of RFC 9110, section 5.6.7, are taken: the one servers must send, "Sun, 06 Nov 1994 08:49:37 GMT", and the obsolete RFC 850 and asctime() ones, "Sunday, 06-Nov-94 08:49:37 GMT" and "Sun Nov 6 08:49:37 1994". UTC is taken for GMT. RFC 850's two-digit year is read as RFC 9110 asks, against the year the library's source dates from. Anything else counts as no Date header, and so does a response with several that disagree or one in another form, a date earlier than the source of the library, which no server running properly can send, or one more than EBISU_DATE_CEILING_YEARS after it, 15 unless the build sets another, 0 for no limit: a server's clock that far ahead is wrong too.

The date is cleared when khc_perform(khc_t*) starts, at each response's status line, so that an interim 1xx response's never stands for the final one's, and by khc_reset_except_cb(khc_t*) and khc_reset_except_request(khc_t*). It is when the server sent the response: read it right after khc_perform(khc_t*), and count from there with the device's own clock.

Parameters
[in]khcinstance.
Returns
Seconds since 1970-01-01T00:00:00Z when the response had a Date header, -1 otherwise.

◆ khc_perform()

khc_code_t khc_perform ( khc_t * khc)

Perform the HTTP session.

During the session, the socket set by khc_set_socket(khc_t*, ebisu_socket_t*), and callback functions set by khc_set_cb_read(khc_t*, KHC_CB_READ, void*), khc_set_cb_write(khc_t*, KHC_CB_WRITE, void*) and khc_set_cb_header(khc_t*, KHC_CB_HEADER, void*) called.

Each call starts from the request alone: what the last one's response left behind is reset first, as by khc_reset_except_request(khc_t*). A body is read through the read callback each time, which must start it over.

A server may answer before the request's body is sent whole, with a 401 or a 413 for instance, and close the connection. With a socket that has recv_wait, khc looks for that before each part of the body, and after a send that fails, as RFC 9112, section 9.5, has a client do: it stops sending, reads the response, and returns as for any other, its status code the server's, with the rest of the body neither read nor sent. An interim 1xx response with nothing after it has the rest sent after all. Without recv_wait, khc reads once the request is sent, and a send that fails fails the request.

This method blocks until the HTTP session ends.

Parameters
[in,out]khcinstance.
Returns
KHC_ERR_OK if the response was read whole. KHC_ERR_FAIL, without connecting, if the socket, one of its operations other than recv_timed_out, the write callback or the header callback is not set. The read callback may be left out for a request with no body. KHC_ERR_FAIL too, without connecting, for a buffer set with a size of 0 by khc_set_resp_header_buff(khc_t*, char*, size_t) or khc_set_stream_buff(khc_t*, char*, size_t).

◆ khc_reset_except_request()

void khc_reset_except_request ( khc_t * khc)

Prepare to perform the same request again.

Resets what sending the last request and reading its response left behind, so that the next khc_perform(khc_t*) sends the request again. The request itself – host, path, method, headers and the body length set by khc_set_req_body_length(khc_t*, size_t) – remains, as do callbacks/ userdata, the settings of khc_enable_insecure(khc_t*, bool) and khc_enable_absolute_target(khc_t*, bool), and the buffers set by khc_set_stream_buff(khc_t*, char*, size_t) and khc_set_resp_header_buff(khc_t*, char*, size_t).

The body is read again through the read callback, which must start it over.

khc_perform(khc_t*) does the same when it starts, so the same request can be performed again without this. What this adds is clearing the last response's results, such as khc_get_status_code(khc_t*), before then.

Parameters
[out]khcinstance.

At EBISU_LOG_DEBUG, each request as it goes: when connected, the request line, each header, and how long the body is, then the response's status line, each of its headers, and how long its body is. Set the length of the request body.

With the length known, the body is sent with a Content-Length header rather than chunked, which some intermediaries handle poorly. The read callback set by khc_set_cb_read(khc_t*, KHC_CB_READ, void*) is asked for no more than is left of it, and has to give all of it: returning 0 before then fails the request with KHC_ERR_READ_CALLBACK, as the server would wait for the rest.

Set response header buffer.

Set response header buffer pointer used by KHC_CB_HEADER. If this method is not called or set NULL to the buffer, khc allocates memory of response header buffer when the HTTP session started and free when the HTTP session ends. The buffer allocated by the khc is 256 bytes.

The buffer is used to store single HTTP response header. If header is larger than the buffer, the header is skipped and KHC_CB_HEADER is not called, which khc_get_resp_header_skipped(khc_t*) tells. khc needs to parse Status Line, Content-Length, Transfer-Encoding header to process HTTP message. The buffer must have enough size to store those headers: khc_perform(khc_t*) returns KHC_ERR_TOO_LARGE_DATA if it doesn't. 256 bytes would be enough. If you set the buffer by the method, the method must be called befor khc_perform(khc_t*) and memory used by the buffer can be safely freed after khc_perform(khc_t*) returned.

Set stream buffer.

Set stream buffer pointer used by KHC_CB_READ, KHC_CB_WRITE. If this method is not called or set NULL to the buffer, khc allocates memory of stream buffer when the HTTP session started and free when the HTTP session ends. The buffer allocated by khc is 1024 bytes.

The request body is sent a buffer at a time, in one write each: over TLS, at least one record each. 1024 bytes suit bodies of a few KB. For larger ones, on a slow or metered link, 4096 bytes or more send fewer, larger records, and responses are read in larger pieces too. A chunked body needs room for a chunk's size line and CRLF besides its data, a few bytes: with no room for data, khc_perform(khc_t*) returns KHC_ERR_TOO_LARGE_DATA. If you set the buffer by the method, the method must be called befor khc_perform(khc_t*) and memory used by the buffer can be safely freed after khc_perform(khc_t*) returned.

◆ khc_set_timeout_ms()

void khc_set_timeout_ms ( khc_t * khc,
uint32_t timeout_ms )

Set how long a request may take.

From the start of khc_perform(khc_t*) to the end of the response. Once it has passed, khc_perform(khc_t*) closes the connection, if one is open, and returns KHC_ERR_TIMEOUT. It is checked between steps, so a socket operation that blocks runs to its own timeout first: it bounds a response that trickles in through receives that each end in time, or a slow handshake made of many.

It needs the monotonic_ms of the system set by khc_set_system(khc_t*, ebisu_system_t*): without one, khc_perform(khc_t*) returns KHC_ERR_FAIL without connecting. khc_init(khc_t*) sets none, and the resets leave it.

[out]khcinstance.
[in]timeout_msThe longest a request may take, in milliseconds, or 0 for no limit.
