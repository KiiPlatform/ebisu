Finds the value a path leads to in a JSON string, and reads it as an integer within [min, max], in one call: jkii_find_member() and then jkii_member_integer(), with the flags' options.

Each result says what was found, so that a value that isn't there can be told from one that is but is refused, without a second lookup:

int64_t interval = 60;
jkii_member_t found;
switch (jkii_find_integer(body, body_len, "/interval", 1, 3600,
JKII_READ_UNQUOTE, &interval, &found)) {
case JKII_FIELD_ERR_OK:
case JKII_FIELD_ERR_NOT_FOUND:
break; // interval as read, or as it was.
default:
// Refused: found is the value as the document wrote it.
log_refused("interval", found.value, found.value_length);
}

Gives the value a path leads to in a JSON string, as jkii_next_member() gives a member: one value, where jkii_parse() reads several. The string is checked as jkii_parse() does. The path is as jkii_field_t::path has it: "/name" for a member of the root, "/a/b/[0]" through objects and arrays, with \/, \[, \] and \\ for those characters in a name. A name is compared as the document writes it, escapes and all, and an object's first member of that name is taken, as jkii_parse() takes it. The value comes with jkii_member_t::key NULL.

Gives the member of the root object of a JSON string that has a name, as jkii_next_member() gives a member, key and all. The name is plain, with no path syntax: "a/b", "[0]", "a.b" and "" are names like any other. It is compared with each member's name unescaped, so "a\u0062" is the member ab, unlike a jkii_find_member() path, whose names are compared as written. The first member of that name is taken, as jkii_parse() takes it.

◆ jkii_member_unquote()

const jkii_member_t * jkii_member_unquote ( const jkii_member_t * member,
jkii_member_t * unquoted )

A string holding a number, true or false, as that value, for the readers. For JSON that sends a number or a boolean in a string: "30", "-2.5", "3e1", "true". The readers take only their own JSON type: through this, a caller takes such a string too, as in jkii_member_integer(jkii_member_unquote(&m, &u), 1, 3600, &value).

A string is taken only if its characters, as written between its quotes, are exactly a JSON number, true or false, as ECMA-404 has them. So " 30", "30 ", "+30", "030", ".5", "0x1E", "NaN", "Infinity", "TRUE", "null" and "" are not, nor is a string with an escape, "\u0033\u0030" included. A string taken reads as the value would: "30.5" is no integer, and "1e400" is JKII_FIELD_ERR_NUM_OVERFLOW as a double.

Parameters
[in]memberThe member, as jkii_next_member(), jkii_root_value() or jkii_find_member() gives it.
[out]unquotedSet, if member is such a string, to the member with the type of what the string holds, as the value would have it; with the same key and the same characters.
Returns
unquoted, if member is such a string; member itself otherwise, a string or not, for the readers to read or refuse as it is.

Parse JSON string.

The string has to be one JSON object or array, after whitespace if any, and before whitespace if any: valid JSON, as ECMA-404 has it, which is checked whole, nesting objects and arrays at most 32 levels deep. Nothing is allocated, and the string is not changed. Anything else is jkii_parse_err_t#JKII_ERR_INVALID_INPUT, and each field's jkii_field_t::result jkii_field_err_t#JKII_FIELD_ERR_NOT_FOUND. So is a field whose value is a number of more than 310 characters, DBL_MAX_10_EXP + 2, with a fraction or an exponent: JSON, but longer than jkii reads.

Gives the value a JSON string is, of any type, as jkii_next_member() gives a member.

The string is checked as jkii_parse() does, but may be any value, not only an object or an array: a string, a number, true, false or null too. The value comes without the whitespace around it, as jkii_member_t has it, and without a key. An object or an array can then be walked with jkii_next_member() on jkii_member_t::value.
