Detailed Description

Writing JSON, bounded, into a buffer or out through a callback.

The writer puts in the commas, colons and quotes itself, escapes strings, and refuses what wouldn't be JSON rather than writing it. It allocates nothing and doesn't recurse: its state is the struct, which can live on a small task's stack.

char body[128];
jkii_writer_t w;
size_t len = 0;
jkii_writer_init_buff(&w, body, sizeof(body));
jkii_write_object_start(&w);
jkii_write_key(&w, "power");
jkii_write_bool(&w, 1);
jkii_write_key(&w, "temperature");
jkii_write_double(&w, 21.5, 1);
jkii_write_object_end(&w);
if (jkii_writer_finish(&w, &len) == JKII_WRITE_OK) {
// body is {"power":true,"temperature":21.5}, len 33.
}

Each call returns the first error so far, so checking the result of jkii_writer_finish() alone is enough.

It writes JSON Lines too, one value a line: jkii_write_record_end() after each value ends its line, and the next value starts the next one. Through a callback, a batch of records can go out as a request body, or be appended to a file, without the batch being held whole.

◆ jkii_write_err_t

enum jkii_write_err_t

Results of writing.

Enumerator
JKII_WRITE_OK 

Written.

JKII_WRITE_ERR_TOO_LARGE 

The output doesn't fit in the buffer. Writing stops, but goes on counting, so that jkii_writer_finish() says how much would have been needed.

JKII_WRITE_ERR_STRUCTURE 

Not where it can go: a value where a key is expected, a key where a value is, the end of a container that isn't open, a second value at the top without jkii_write_record_end() between, jkii_write_record_end() with no value whole before it, or jkii_writer_finish() with containers still open or nothing written.

JKII_WRITE_ERR_TOO_DEEP 

Objects and arrays nested deeper than JKII_WRITER_MAX_DEPTH.

JKII_WRITE_ERR_VALUE 

A value JSON can't hold, or a NULL one: NaN, an infinity, a double too large for its decimals, more than 9 decimals, or raw JSON of no length.

JKII_WRITE_ERR_CALLBACK 

The write callback took less than it was given.

jkii_write_err_t jkii_write_double ( jkii_writer_t *  w,
double  v,
int  decimals 
)

Writes a number with a fixed number of decimals.

Rounded to the nearest, half away from zero, with '.' whatever the locale, and without printf, which some embedded C libraries build without floating point. The rounding is done in double, so a value within the double's precision of a half, such as 0.995 with 2 decimals, can come out one off in the last decimal. A value that rounds to 0 is written without a sign.

Parameters
[in,out]wThe writer.
[in]vThe value. NaN and the infinities are JKII_WRITE_ERR_VALUE, as is a value whose magnitude times 10 to the decimals is 2 to the 64 or more.
[in]decimalsDigits after the point, 0 to 9. With 0 there is no point.
Returns
JKII_WRITE_OK or the first error so far.

◆ jkii_write_record_end()

jkii_write_err_t jkii_write_record_end ( jkii_writer_t *  w)

Ends a record of JSON Lines: the value at the top, which has to be whole, is followed by '\n', and the next value starts another record.

Neither an array around the records nor commas between them are written. jkii_writer_finish() then accepts what was written, whether or not the last record was ended.

A record written by a writer of its own, ended with this, is a line to append to a file of JSON Lines. Written into a buffer, it can be appended with one write, so that a write cut short leaves at most that line cut short. If the file doesn't end with '\n', as when its last write was cut short, write one first: the new record then starts a line of its own, rather than running on from what was cut short.

Parameters
[in,out]wThe writer.
Returns
JKII_WRITE_OK or the first error so far: JKII_WRITE_ERR_STRUCTURE if no value is whole at the top.

void jkii_writer_init_buff ( jkii_writer_t *  w,
char *  buff,
size_t  buff_size 
)

Sets up a writer into a buffer.

Once jkii_writer_finish() has succeeded, the buffer holds the JSON, terminated, so it has to be at least one byte longer. With buff NULL and buff_size 0, nothing is written, and jkii_writer_finish() says how long the JSON is: a dry run, to size a buffer.

Parameters
[out]wThe writer.
[out]buffThe buffer, or NULL for a dry run.
[in]buff_sizeIts size.

char *  buff,

Sets up a writer out through a callback.

buff collects the output, and is given to cb whenever it is full, and at jkii_writer_finish(), so the JSON can be longer than buff: a request body, or a file. Any size from 1 works, and a larger one means fewer calls. The output isn't terminated.

Parameters
[out]wThe writer.
[out]buffThe buffer the output is collected in.
[in]buff_sizeIts size, at least 1.
[in]cbTakes the output.
[in]userdataGiven to cb.
